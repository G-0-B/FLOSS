# Holo-RBI Recursive Event Swarm Synthesis — Delta vs FLOSSI0ULLK Canon

This note digests an externally produced synthesis ("Holo-RBI Recursive Event
Swarm 2.0") that arrived as a chat paste on 2026-07-07. The synthesis was
generated by another AI session over a user-uploaded paper set (System Scaling,
ObjectGraph, TRINITY, Conductor, constraint-drift, Positive Alignment,
Strategic Patience, TAME, Right to Be Remembered, DeAI experiential agents) and
frames a six-layer "agentic operating layer" around a trading-oriented
Research→Backtest→Implement (RBI) swarm.

This is a comparison artifact only. It adopts nothing. Every claim inherited
from the synthesis is 🔮 Aspirational — the synthesis cites no verified repo
artifacts, and its paper summaries have not been independently re-checked here
(two of its papers, Conductor and Positive Alignment, were already digested
directly; see references above).

## Verdict

Roughly 70% of the synthesis restates things FLOSSI0ULLK has already specified
or built under different names. One proposal contradicts a settled decision
(ADR-10 router-not-controller). Four items are genuine deltas worth tracking.
The trading vertical is out of scope for this doc (see §Non-goals).

## Conflict: router vs controller

The synthesis's Coordinator layer (TRINITY/Conductor-style: assigns roles,
picks models, routes outputs, designs communication topology) is a
**controller** pattern. ADR-10 deliberately built a **passive router**: the
gateway accepts Claims/Votes and appends to the source chain; it does not
decide outcomes or command voters. This is load-bearing for consent-based
governance and for the diversity policy (≥3 provider surfaces, ≥4 model
families counted as *independent* voters — a commanding coordinator erodes
that independence).

Prior art in-repo: the 2026-05-18 Conductor digestion already settled the
adoption shape — Conductor-style orchestration is an *orchestration-policy
candidate*, never a new authority layer; truth authority stays with ADRs,
source-chain claims, and integrity validation. This delta reaffirms that and
adds one sharpening:

> If adaptive coordination is pursued, the coordinator must be a **proposing**
> agent whose task assignments are themselves Claims subject to Votes, not a
> commanding one. That shape needs a new ADR before any implementation.

No ADR is opened by this doc. The question is logged here as the trigger
condition.

## Genuine deltas (the ~30%)

1. **Memory expiry/retest discipline.** The synthesis's "memory constitution"
   fields `valid_context`, `known_failures`, and `expiry_or_retest_date` are
   absent from current KnowledgeTriple thinking. Stale-truth decay + scheduled
   retesting is a real gap. **Action pointer:** check against ADR-17 before
   the Phase 1 contract hardens. Correction carried with it: an LLM-emitted
   `confidence` float is an *input* to validation (analog vote territory,
   ADR-17 signed-gradient), never a truth-maker; truth status comes from
   symbolic validation only.
2. **Staged economic-agency ladder** (local → cloud → tool-using →
   approval-gated execution → limited economic agency → self-sovereign).
   Roughly matches current posture but is a cleaner *explicit* progression
   than anything in canon. Candidate for a governance-doc paragraph, not a
   new doc.
3. **Learned coordination** — covered in §Conflict; delta is real, adoption
   shape is constrained.
4. **Application vertical as forcing function.** The synthesis grounds every
   abstraction in one concrete loop with measurable outcomes (backtests,
   Sharpe, drawdown). FLOSSI0ULLK's equivalent forcing function is the
   Phase 0 substrate-bridge validation; the reminder is useful, the domain
   is not imported.

## Non-goals

The trading/RBI domain (backtesting.py, risk sentinel, live execution) is a
separate project scope, not FLOSSI0ULLK material. If it becomes real, it is
its own repo/canon and at most a *consumer* of this substrate. It does not
ride into FLOSS canon via this research delta.

## Disposition

- No canon change. No ADR opened. No spec touched.
- Follow-ups logged: (a) ADR-17 review to consider expiry/retest +
  valid-context/known-failures fields; (b) proposing-coordinator ADR question,
  dormant until someone actually wants adaptive orchestration; (c) optional
  governance paragraph for the economic-agency ladder.
